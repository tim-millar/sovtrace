# SOVTrace v0.1.0

## Overview

SOVTrace is a local Python CLI for querying supported insurance Schedule of Values
workbooks. This is its first formally versioned GitHub source release.

## Capabilities

SOVTrace imports supported `.xlsx` workbooks into local SQLite, maps supported
Schedule of Values concepts, and handles bounded existence, logical-asset count,
total-insurable-value sum, and asset-list questions. Optional model-assisted
schema interpretation and SQL generation are available. Generated SQL is
independently validated before restricted, read-only SQLite execution. Monetary
calculations use exact integer micro-USD. Results retain original source-cell
evidence and reconcile contributing records against the query result. Finite
resource ceilings and fail-closed checks bound supported operations.

It does not interpret arbitrary spreadsheets or arbitrary natural-language
questions.

## Getting started

Prerequisites are Python 3.12, `uv`, an extracted source archive or repository
checkout, and network access for ordinary dependency installation where needed.
From the project directory:

```sh
uv sync --locked
uv run --locked sovtrace --version
uv run --locked python scripts/demo.py
```

See the [README](https://github.com/tim-millar/sovtrace/blob/v0.1.0/README.md) for
more commands and examples. GitHub-generated source archives contain project
source; they do not include preinstalled dependencies or a standalone executable.

## Offline verification and evaluation

The deterministic demonstration imports a synthetic workbook with 4 logical
assets and 5 physical source records, then runs 8 fixed questions. Its SQL is
predefined by a simulated generator: SQL validation, SQLite execution, arithmetic,
and evidence reconciliation are real application operations. The five-step case
study uses a separate simulated generator and also exercises a successful answer,
an unsupported question, and rejected SQL.

The synthetic offline evaluation covers 14 artificial fixtures and 80 question
outcomes, including deliberate refusals and ingestion rejections. Its outcomes
describe those fixed synthetic cases only. These checks do not measure live-model
interpretation or accuracy and do not guarantee semantic correctness for a user's
intent.

## Optional model-backed operation

The existing authenticated workflow requires authorized model access and may incur
charges. Workbook headings, questions, and semantic schema information may be sent
to an external model provider, depending on the selected workflow. Review the
README's [data exposure and privacy guidance](https://github.com/tim-millar/sovtrace/blob/v0.1.0/README.md#what-leaves-the-machine)
before using sensitive inputs. Provider handling and retention depend on the
provider account and configuration.

## Limitations

- Only supported workbook structures, concepts, and bounded question operations
  are handled.
- SQL is restricted and read-only; operations outside the supported set fail
  closed.
- Finite resource ceilings do not provide unlimited protection against resource
  exhaustion.
- Source reconciliation verifies execution and evidence for a validated
  interpretation; it does not prove correct interpretation of arbitrary user
  intent.
- No support or maintenance commitment is established for a particular release.
